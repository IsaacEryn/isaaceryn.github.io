# aria-live 상태 메시지 체험

블로그 포스트 [aria-live 상태 메시지, 스크린 리더는 어떻게 읽을까 — WCAG 4.1.3](https://www.codeslog.com/posts/aria-live-status-messages/)의 데모.

## 구성

| 앵커 | 시연 |
|---|---|
| `#polite-assertive` | 장바구니 연속 담기에서 polite(큐 적체) vs assertive(발화 끊김) 비교 |
| `#debounce` | 화면 표시는 즉시, 발화는 마지막 클릭 600ms 뒤 한 번 (디바운스) |
| `#silent` | live region 없이 텍스트만 변경 — 조용한 실패 (WCAG F103) |
| `#non-text` | 아이콘·알림음 상태: 대체 텍스트(1.1.1)+role(4.1.3) 조합의 유무 비교 |
| `#not-status` | 설문 새 질문 — 상태 메시지가 아닌 변화. 조용히 추가 vs polite 사후 안내 vs 선택지 라벨 사전 안내(모범 사례) |

## 설계 노트

- **가상 스크린 리더 패널**: 발화 시간을 글자 수(55ms/자, 최소 700ms)로 근사해 큐를 시각화한다.
  스펙(WAI-ARIA 1.2 aria-live)이 말하는 우선순위의 모형일 뿐, 실제 제품 동작이 아니다 —
  패널 상단에 그렇게 표기했고, 실제 확인용으로 페이지의 모든 알림 영역은 진짜 live region으로 뒀다.
- 가상 패널은 `aria-hidden="true"`다. 실제 스크린 리더 사용자는 같은 정보를 진짜 알림으로 이미 듣기
  때문에 패널까지 읽히면 이중 낭독이 된다. polite 무대에는 그 사실을 설명하는 `sr-only` 노트가 있다.
- 버튼 `focus` 시 가상 패널에 "…, 버튼" 발화를 끼워 넣어, 버튼 이름 낭독과 알림이 경합하는 실제
  상황(질문의 출발점)을 재현했다.
- 알림음은 WebAudio 사인파(880Hz, 0.35s)라 외부 에셋이 없다. 소리'만'의 상태 전달이 왜 부족한지
  보여주는 장치로, 항상 텍스트 상태 메시지와 함께 낸다.
- 언어 전환·스타일은 저장소 공통 규약(`shared.css`, `data-i18n`+`EN` 사전, `?lang=` 딥링크) 준수.
